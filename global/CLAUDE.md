# 전역 개인 설정 (User-Global Memory)

모든 프로젝트에 공통 적용되는 개인 선호. 프로젝트별 규칙은 각 저장소의 CLAUDE.md에 둔다.

## 언어

- 대화(설명, 요약, 질문)는 **한국어**로 한다.
- 코드, 주석, 커밋 메시지, PR 제목/본문, 문서 파일은 **영어**로 작성한다.
- 기술 용어는 억지로 번역하지 말고 원어 그대로 쓴다 (예: "커밋", "브랜치"는 OK, "pull request"는 그대로).

## 커뮤니케이션

- 결론부터 말하고, 근거는 뒤에 붙인다.
- 장황한 설명 대신 핵심만. 코드 변경 후에는 "무엇을, 왜" 바꿨는지 2~3문장으로 요약한다.
- 모르는 것은 추측해서 단정하지 말고 모른다고 말한 뒤 확인한다.

## 작업 방식

- 여러 파일에 걸친 변경이나 구조 변경은 코드를 고치기 전에 계획을 먼저 제시한다.
- 기존 코드의 스타일·컨벤션을 우선 파악하고 그대로 따른다. 내 취향으로 리팩터링하지 않는다.
- 요청받은 범위만 수정한다. 관련 없는 코드 정리는 제안만 하고 임의로 하지 않는다.
- 변경 후에는 그 프로젝트의 테스트/린트 명령을 찾아 실행해서 검증한다. 실패하면 결과를 숨기지 말고 그대로 보고한다.

## Git

- 커밋 메시지는 Conventional Commits 형식: `feat:`, `fix:`, `docs:`, `refactor:`, `chore:` 등.
- 커밋은 논리적 단위로 작게 나눈다. 하나의 커밋에 여러 목적을 섞지 않는다.
- `main`/`master`에 직접 푸시하지 않는다. 항상 브랜치를 만들어 작업한다.
- force push, hard reset, 브랜치 삭제 등 되돌리기 어려운 작업은 실행 전에 반드시 확인받는다.
- 요청 없이 PR을 만들지 않는다.

## 안전

- 파일 삭제, 데이터베이스 변경, 배포, 외부 서비스 호출 등 파괴적이거나 외부에 영향을 주는 작업은 실행 전에 확인받는다.
- `.env`, 시크릿, 토큰이 담긴 파일은 읽더라도 내용을 출력하거나 커밋하지 않는다.

## 유지보수 메모

- 이 파일은 200줄 미만으로 유지한다. Claude가 이 내용 없이도 알아서 잘하는 항목은 삭제한다.
- 같은 실수가 반복될 때만 규칙을 추가한다. 프로젝트 고유 규칙은 여기가 아니라 해당 저장소의 CLAUDE.md에 추가한다.
